# Прогон нефтяных новостей по регионам

## Текущий план: США, SA, AE и завершение частичных индексов

С 2026-11-10 очередь индекса Media Cloud: **US → SA → AE → IT → ES → OM → AZ**
(`us,sa,ae,it,es,om,az`), одним ключом `MEDIACLOUD_API_KEY` из `.env` и одним
процессом. После Саудовской Аравии и ОАЭ докачиваются частичные индексы Италии,
Испании, Омана и Азербайджана. Все готовые месяцы, включая весь индекс США,
пропускаются. Остальные страны в очередь загрузки не добавляются.
Дополнительные `mediacloud*.env` не используются.

При этом обрабатываются **все уже скачанные окна всех регионов**, включая
неполные US, OM, IT, ES и AZ. Частичный датасет не означает покрытие всех
142 месяцев: покрытие индекса видно в `status`.

На этой машине:

```bash
~/Projects/oil-news-start.sh
```

Это обёртка над [`scripts/start_news.sh`](../scripts/start_news.sh). Скрипт:

- останавливает таймер старого `oil-news-process`, затем по одному явно
  размораживает замороженные старые сервисы `oil-news-download-{a,b,c,d,e}`
  и `oil-news-process` и сразу останавливает каждый; отдельно размораживать
  их не нужно;
- останавливает прежний `oil-news-us`, если он ещё загружен, и запускает
  единственный `oil-news-index`:
  `run --stage download --only us,sa,ae,it,es,om,az`,
  последовательно одним ключом из `.env`;
- при ошибке загрузки повторяет попытку через час;
- запускает независимые обработчики классификации, текстов и снимков датасетов;
- использует существующий `.venv/bin/python`, без переключения окружений через uv.

Нужны готовое окружение (`uv sync --all-groups`) и доступ к systemd user bus.
Повторный запуск сохраняет уже работающие новые обработчики.
Если при паузе таймер исчез, а замороженный сервис остался загружен, launcher
размораживает сервис и создаёт только его таймер, сохраняя текущий процесс.

| Unit | Работа | Повтор после завершения |
|---|---|---|
| `oil-news-index.service` | US → SA → AE → IT → ES → OM → AZ; готовые окна пропускаются | Ошибки: через час |
| `oil-news-filter.timer` | Склейка доступных окон, классификация, кандидаты | 30 минут |
| `oil-news-texts.timer` | До 5000 новых страниц на регион, свежие сначала; датасеты | 5 минут |
| `oil-news-snapshot.timer` | Датасеты из уже сохранённых текстов, без сети | 15 минут |
| `oil-news-awake.service` | Запрет сна во время прогона | Постоянно |

Каждый проход текстов посещает США первыми, затем остальные прибывшие регионы.
Лимит 5000 страниц не даёт большому региону задержать первые датасеты всех
остальных. Следующий проход продолжает со следующих нескачанных статей.
Глобальный лимит запросов к издателям остаётся 32, к одному сайту — 4.
Media Cloud используется только загрузчиком индекса, обработчики к нему
не обращаются.

Классификатор использует CUDA автоматически, если она доступна. CPU в это
время занимается извлечением текста в другом процессе. Настройки `.env`:

```text
# Необязательное явное устройство; без него — автовыбор.
FILTER_DEVICE=cuda:0
FILTER_BATCH_SIZE=64
```

Принудительный `cuda:0` завершит классификацию ошибкой, если CUDA недоступна.
Для CPU можно поставить `FILTER_DEVICE=cpu`. Лимит текстов задаётся переменной
`FULLTEXT_REGION_LIMIT`; launcher устанавливает 5000. В обычных CLI-командах
по умолчанию лимита нет.

### Ограничение нагрузки CPU

Launcher ограничивает `oil-news-index`, `oil-news-filter`, `oil-news-texts`
и `oil-news-snapshot`
значением `CPUQuota=85%`: это 0,85 логического CPU на каждый сервис, а не 85%
всей машины. Перед ограничением классификатор потреблял около 108% одного CPU
на трёхсекундном замере; квота 85% составляет примерно 80% этой нагрузки.
Это не ограничение температуры и не квота GPU.

Повторный запуск `~/Projects/oil-news-start.sh` применяет квоту к уже работающим
сервисам без перезапуска; новые сервисы создаются с такой же квотой.
При необходимости задать другую квоту:

```bash
OIL_NEWS_CPU_QUOTA=70% ~/Projects/oil-news-start.sh
```

Без переменной окружения launcher каждый раз использует 85%.

По логу 2026-11-09 France: классификация 151564 заголовков заняла около
4 минут 38 секунд (15:16:41–15:21:19), CUDA уже использовалась. `77000` в колонке
`texts` означало попытки скачать страницы, а не классификацию. GPU не ускоряет
сетевое ожидание. При необходимости отдельного ускорения энкодера см.
[документацию Sentence Transformers](https://www.sbert.net/docs/sentence_transformer/usage/efficiency.html).

## Ручные команды

Из корня репозитория, в отдельных терминалах:

```bash
# US → SA → AE → IT → ES → OM → AZ последовательно, ключ из .env.
env -u MEDIACLOUD_API_KEY -u VIRTUAL_ENV uv run python -m news run \
  --stage download --only us,sa,ae,it,es,om,az

# Склеить в том числе частичные индексы, оценить новые окна всех регионов.
uv run --group ml python -m news run --stage filter

# Скачать тексты уже готовых кандидатов, без загрузки энкодера.
FULLTEXT_REGION_LIMIT=5000 uv run python -m news run --stage fulltext

# Немедленно собрать всё, для чего тексты уже сохранены: без сети и torch.
uv run python -m news run --stage assemble
```

Не запускайте ручной загрузчик одновременно с `oil-news-index.service`, а ручные
`filter` и `fulltext` — одновременно с соответствующим systemd обработчиком.
В штатной схеме у каждого этапа один writer; обновления parquet атомарны,
поэтому другой этап не прочитает недописанный индекс, кандидатов или датасет.

`--only us,fr` ограничивает любой `run --stage ...` выбранными регионами.
`run --stage process` остаётся последовательной командой: сначала снимки
сохранённых текстов, затем классификация всех доступных регионов, затем тексты.

Индекс не обязательно докачивать целиком: новые окна попадут в склейку при
следующем `filter`, а уже оценённые окна повторно не считаются. Датасеты можно
собирать до окончания загрузки текстов; снимок содержит только успешно
извлечённые статьи после чистки шаблонов и уточнения дат. Истории без текстов
остаются в индексах и кандидатах, а не выдаются за готовые статьи.

## Как следить и остановить

```bash
uv run python -m news status
systemctl --user list-units 'oil-news-*' --all --no-pager
tail -f data/logs/news.log
```

| Колонка | Что значит |
|---|---|
| `months` | Скачано месяцев индекса из 142 |
| `index` | Историй в склеенном индексе, в том числе частичном |
| `filtered` | Оценено файлов индекса из скачанных файлов |
| `candidates` | Прошло фильтр заголовков |
| `texts` | Попыток скачать текст, включая ошибки и повторные попытки |
| `dataset` | Успешных статей в последнем снимке датасета |
| `updated` | Последнее изменение файлов региона |

Остановить загрузку, обработку и запрет сна:

```bash
systemctl --user stop oil-news-{filter,texts,snapshot}.timer \
  oil-news-{index,filter,texts,snapshot,awake}.service
```

Продолжить: `~/Projects/oil-news-start.sh`. Старые download units размораживать
не нужно.

Для переезда можно сохранить работающие процессы замороженными:

```bash
systemctl --user stop oil-news-{filter,texts,snapshot}.timer
for unit in oil-news-{index,filter,texts,snapshot}.service; do
  if systemctl --user is-active --quiet "$unit"; then
    systemctl --user freeze "$unit"
  fi
done
systemctl --user stop oil-news-awake.service
```

После подключения к сети достаточно `~/Projects/oil-news-start.sh`: он сам
размораживает сохранившиеся сервисы и восстанавливает таймеры.

## Результаты

- `data/raw/news/{регион}/mediacloud/` — скачанные окна индекса;
- `data/interim/news/{регион}/stories.parquet` — склеенный индекс;
- `data/interim/news/{регион}/filtered/` — оценки заголовков;
- `data/interim/news/{регион}/candidates.parquet` — прошедшие фильтр истории;
- `data/processed/news/{регион}/oil_news.parquet` — статьи с текстами.

Данные не идут в git. Для передачи:

```bash
tar -czf oil_news_regions.tar.gz data/processed/news data/interim/news
```

Справочник всех 49 регионов и метод отбора — в
[`src/news/README.md`](../src/news/README.md). Для нынешнего запуска весь список
регионов не является очередью дальнейшей выкачки.
