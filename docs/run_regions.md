# Полный прогон нефтяных новостей по регионам

Инструкция для запуска на отдельном компьютере, который можно оставить работать
на дни. Что делает пайплайн и почему он так устроен — в
[`src/news/README.md`](../src/news/README.md).

## Что получится

49 регионов (США, Ближний Восток, ЕС-27, Казахстан, Азербайджан, Венесуэла,
Мексика, Китай, Индия), 2015-01-01 – 2026-10-31:

- индекс Media Cloud — около **9,4 млн** заголовков: recall-запрос по
  нефтяным терминам, у Ирака, Йемена, Омана и Сирии — весь поток;
- классификатор заголовков оставит около **3,8–4 млн** историй;
- для них качаются тексты, итог — `data/processed/news/{регион}/oil_news.parquet`.

## Сколько это займёт

| Этап | Объём | Время | Что ограничивает |
|---|---|---|---|
| `download` | ≈ 11 тыс. запросов к Media Cloud | **≈ 3 недели** | квота 4000 запросов в неделю и 2 запроса в минуту (≈ 33 ч на недельную квоту) |
| `process`: фильтр | 9,4 млн заголовков | ≈ 13 ч на Apple M (MPS), на CPU — в разы дольше | энкодер `multilingual-e5-base` |
| `process`: тексты | ≈ 3,9 млн страниц | **≈ 5 суток** | ≈ 9 страниц в секунду, 32 одновременных загрузки |

Оценки — по выборке из 20 тыс. историй и пробному прогону Сирии за октябрь 2026
(7921 заголовок: фильтр 37 с, оставлено 829, тексты 826 из 829 за 3 мин).

Место на диске: ≈ 15 ГБ — индекс ≈ 1,6 ГБ, тексты ≈ 5 ГБ, датасеты ≈ 3 ГБ,
модель с Hugging Face ≈ 1,1 ГБ, окружение с torch ≈ 3 ГБ.

## Подготовка (один раз)

1. Установить [uv](https://docs.astral.sh/uv/) — см. «Установка uv» в
   [README](../README.md).
2. Склонировать репозиторий и поставить зависимости, включая группу `ml`
   (torch, sentence-transformers):

   ```bash
   uv sync --all-groups
   ```

3. Положить в `.env` в корне репозитория ключ Media Cloud (образец —
   `.env.example`):

   ```text
   MEDIACLOUD_API_KEY=...
   ```

   Квота считается на ключ: пока идёт прогон, с этим ключом нигде больше
   не качать.

Модель заголовков уже в репозитории (`data/models/news/title/meta.json`),
энкодер скачается с Hugging Face при первом `process`. DeepSeek для прогона
не нужен.

## Запуск

Две стадии в двух терминалах; обе можно прерывать и перезапускать — сделанное
пропускается.

**Терминал 1 — выкачка индекса.** Регионы идут по порядку `regions.toml`:
США → Ближний Восток → ЕС → остальные.

```bash
uv run python -m news run --stage download
```

Когда квота кончится, команда упадёт с ошибкой Media Cloud. Это нормально:
повторить через несколько часов (квота возвращается в течение недели), прогон
продолжится с первого недокачанного месяца.

**Терминал 2 — обработка.** Берёт регионы, индекс которых уже склеен: фильтр,
тексты, датасет. Запускать, когда в терминале 1 появились готовые регионы,
и повторять, пока не обработаются все.

```bash
uv run --group ml python -m news run --stage process
```

Отдельные регионы — через `--only`, например `--only us,sa`.

Чтобы компьютер не засыпал: на macOS — префикс `caffeinate -i` перед командой,
на Windows — «Электропитание → Никогда не переводить в спящий режим».

## Как следить

- Логи пишутся в терминал: по строке на окно индекса, на месячный файл фильтра
  и на пачку из 500 текстов.
- Готовность по регионам — файлы:
  - `data/interim/news/{регион}/stories.parquet` — индекс склеен;
  - `data/interim/news/{регион}/candidates.parquet` — фильтр пройден;
  - `data/processed/news/{регион}/oil_news.parquet` — датасет готов.

## Что вернуть

Каталоги `data/processed/news/` (датасеты с текстами) и `data/interim/news/`
(индексы, вероятности фильтра, кандидаты без текста). В git данные не идут —
передать архивом:

```bash
tar -czf oil_news_regions.tar.gz data/processed/news data/interim/news
```
